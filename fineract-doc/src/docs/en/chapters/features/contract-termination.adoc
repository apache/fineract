= Contract Termination and Loan Withdrawal

== Goal

Contract Termination allows financial institutions to terminate an active loan contract and make outstanding amounts due as of the selected termination date.

FINERACT-2817 extends this functionality to support future transaction dates and introduces Loan Withdrawal as a distinct transaction type with comparable early termination behavior.

Interest is calculated up to the selected effective date using the loan product's existing calculation rules.

== Requirements

=== Eligibility

Both operations require:

* An active loan account with a Progressive repayment schedule.
* An active client or group.
* A loan that is not charged off.
* No existing contract termination or loan withdrawal applied.

=== Transaction Date

* Accept an optional `transactionDate`.
* Default to the current tenant business date when the date is omitted.
* Reject explicitly supplied dates that cannot be parsed.
* Allow transactions on the current business date.
* Allow future dates strictly earlier than the loan's current maturity date.
* Reject backdated contract termination.
* Allow historical loan withdrawal only when its date does not precede:
** The last user transaction date, excluding amortization.
** The submission date of any active charge.

=== Schedule and Interest

* Accelerate unpaid installments to the selected effective date where applicable.
* Make outstanding principal due according to the revised schedule.
* Calculate interest up to the effective date using existing day-count and rounding conventions.
* Remove installments after the effective termination date where schedule acceleration applies.
* Continue delinquency calculations against the revised schedule.
* Apply existing accrual and accounting rules to the revised schedule.

Current-business-date termination after maturity retains existing behavior:
the schedule is not accelerated and the original maturity date remains unchanged.

=== Future-Dated Processing

Future-dated requests are processed when submitted. The transaction carries
the selected future effective date, and the loan substatus and schedule are
updated during processing.

The request is not queued for execution on the future date.

=== User Interface

* Default the date selector to the tenant business date.
* Allow eligible future dates strictly before maturity.
* Prevent past dates for contract termination.
* Apply the historical-date restrictions for loan withdrawal.
* Display server validation errors.
* Show the operation label and effective date in transaction history.

=== Reversal and Subsequent Operations

* Support undo for both contract termination and loan withdrawal.
* Require the corresponding termination transaction to be the last user transaction before undo.
* Reverse the transaction, clear the early termination substatus, regenerate the schedule, and reprocess transactions.
* Preserve existing rules for payments, reversals, charge-off, and charge-back operations.

=== Non-functional Requirements

* Preserve compatibility for requests that omit the transaction date.
* Enforce date and eligibility rules on the server.
* Preserve existing permissions, audit trails, and transaction boundaries.
* Reuse existing interest, allocation, accounting, and schedule processing.

== Configuration

* No additional configuration flag is required.
* The loan product must use a Progressive repayment schedule.
* The tenant business date determines whether a transaction is historical, current, or future-dated.
* Interest calculation follows existing product settings, including interest recalculation, day-count, and rounding rules.
* Existing permissions control application and undo operations.

== API

All endpoints below use `POST` and are relative to the API base path.

[cols="1,2"]
|===
|Operation |Endpoint

|Contract termination
|`/loans/{loanId}?command=contractTermination`

|Undo contract termination
|`/loans/{loanId}?command=undoContractTermination`

|Loan withdrawal
|`/loans/{loanId}?command=loanWithdrawal`

|Undo loan withdrawal
|`/loans/{loanId}?command=undoLoanWithdrawal`
|===

=== Apply Request

The same request fields apply to contract termination and loan withdrawal.

[source,json]
----
{
  "transactionDate": "15 November 2026",
  "dateFormat": "dd MMMM yyyy",
  "locale": "en",
  "externalId": "early-termination-001",
  "note": "Early termination requested by the customer"
}
----

`transactionDate`, `externalId`, and `note` are optional. Supply the appropriate
`dateFormat` and `locale` when specifying a transaction date.

=== Undo Request

[source,json]
----
{
  "note": "Reversing early termination",
  "reversalExternalId": "early-termination-reversal-001"
}
----

The response uses the existing command processing result, including the
transaction identifier, loan identifier, and applicable changes.

== Transaction and Database Impact

[cols="1,1,1"]
|===
|Operation |Transaction type |Loan substatus

|Contract termination
|`CONTRACT_TERMINATION` (38)
|`CONTRACT_TERMINATION` (900)

|Loan withdrawal
|`LOAN_WITHDRAWAL` (48)
|`LOAN_WITHDRAWAL` (901)
|===

* Store the selected effective date in `m_loan_transaction.transaction_date`.
* Update `m_loan.sub_status_enum` for the selected operation.
* Mark the original transaction as reversed when undone.
* Clear the early termination substatus during undo.
* Distinguish loan withdrawal from withdrawal of a loan application.

The early termination transaction itself does not create direct accounting
entries. Related accrual processing may generate transactions and journal entries.

== Business Events

Application publishes the corresponding operation event:

* `LoanTransactionContractTerminationPostBusinessEvent`
* `LoanTransactionLoanWithdrawalPostBusinessEvent`

Undo uses the corresponding reversal event:

* `LoanUndoContractTerminationBusinessEvent`
* `LoanUndoLoanWithdrawalBusinessEvent`

Existing balance-change and transaction-adjustment events remain part of
the relevant processing flows.
